## Context

Issue #170 调整两组既有产品行为：Tauri 默认帮助菜单将扩展为跨平台应用菜单；更新检查不再每次启动都联网并展示持续提示。现有更新链路是 `App.vue` 启动触发、`store/updates.ts` 管理结果与“稍后”记忆，Rust 菜单通过 `update-menu-action` 通知前端。菜单需复用既有 command/store/component 能力，不新增业务 IPC command。

## Goals / Non-Goals

**Goals:**
- 三端菜单结构和动作统一，按歌曲、EULA、开发构建等状态同步菜单启用状态。
- 用稳定的通用菜单 action 事件，由前端集中分发。
- 将成功检查时间持久化，并将自动检查节流到至少 7 天；失败不推进时间，手动操作始终可用。
- 给更新提示加入有界自动关闭和顶栏恢复入口，同时保留版本级“稍后”记忆。

**Non-Goals:**
- 不增加批量编辑、更新自动下载/安装或新的更新服务。
- 不改变 Release 查询、版本比较和 URL 安全校验契约。
- 不要求无更新/失败提示在后台长期保留；按 Issue 中时限和手动关闭行为处理。

## Decisions

- **以 Tauri Menu API 构造共同菜单，平台差异仅保留 macOS 应用菜单。** 文件动作复用 `pick_folder`、当前 Editor 保存、既有列表重读与 `scan_missing`；编辑命令优先采用 Tauri 原生标准菜单项；主题复用 theme store/API；窗口关闭、退出、重载和开发者工具使用 Tauri 原生能力。替代方案是前端自绘菜单，但其不满足系统原生菜单与三端一致要求。
- **通过统一 `app-menu-action` 事件传递稳定 action ID，并由 App 层集中监听/分发。** 菜单启用状态由前端状态变化同步到原生菜单，避免菜单可见状态与动作可用状态脱节；事件监听沿用 `api/client.ts` 的统一 Tauri event 封装。替代方案是每项菜单使用独立事件，会扩大事件契约并分散分发逻辑。
- **最近成功检查时间放入应用 config.json。** 由 Rust 侧 config 持久化，前端更新 store 在检查成功后记录；启动前读取并判断间隔，成功结果（无更新或有更新）都算成功，错误不写。该数据跨应用重启且具应用语义；不选 localStorage，避免其与当前运行时存储策略及 config 读取职责分裂。手动检查成功也更新最近成功时间，但手动调用自身不受节流。
- **更新提示的短时可见性与可用更新状态分离。** Toast 负责 15 秒提示展示/关闭；store 持有可用更新结果并控制顶栏红点，点击红点重新打开提示。无更新 toast 5 秒关闭，错误 toast 不自动关闭。“稍后”继续记录版本但不清除更新结果/红点，避免与 Issue 的恢复入口冲突。
- **菜单状态通过前端同步快照更新。** 保存可用性依赖当前歌曲存在、可写且 dirty；关于按 EULA 状态；开发者工具只在 dev 构建显示。若平台不支持某原生编辑命令，设计阶段优先采用 Tauri 既有标准菜单角色并验证三端表现，不以自定义编辑业务逻辑替代系统行为。

## Risks / Trade-offs

- [不同平台对标准编辑菜单、窗口关闭和原生应用菜单的呈现有差异] → 使用 Tauri 菜单角色并在 macOS、Windows、Linux 构建验证；macOS 特有应用菜单单独构造。
- [前端状态可能在原生菜单状态更新前变化] → 集中同步菜单状态，并在动作分发时再次检查业务状态；测试覆盖状态变更与禁用动作。
- [本地时间被用户调整会影响周期间隔] → 使用持久化 UTC 时间戳并将无效/未来时间视为需要检查；节流仅是减少打扰，不作为安全边界。
- [自动关闭与用户重新打开提示存在计时器竞态] → toast 每次展示维护独立/可清理 timer，关闭旧提示或切换结果时取消旧 timer，并以 store 当前结果作为重开数据源。

## Migration Plan

无需数据迁移：新增最近成功检查时间键，缺失时按首次启动执行检查。旧菜单事件通道随菜单改造整体替换为通用事件；旧版本级“稍后”记录保持兼容。回滚代码后，新增配置键可忽略。

## Open Questions

- 实现前需核实当前配置文件 API 是否允许前端安全读写新增时间字段；若仅 Rust 可读写，须通过既有 command/config facade 扩展，不将文件 IO 放入组件。
- “关闭窗口 / 退出”在 Windows/Linux 是否按主窗口关闭行为实现、macOS 是否仅保留应用菜单 Quit，须结合现有窗口生命周期实现核对并在测试中明确。
