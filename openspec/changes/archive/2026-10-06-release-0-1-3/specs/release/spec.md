## ADDED Requirements

### Requirement: v0.1.3 发布元数据一致
项目面向用户的发布版本 MUST 统一为 `0.1.3`。

#### Scenario: 发布版本可追溯
- **WHEN** 用户查看应用元数据、README 版本徽章或 Git 标签
- **THEN** 它们都指向 `0.1.3` / `v0.1.3`

### Requirement: 发布说明覆盖近期用户功能
README 发布说明 MUST 总结 `v0.1.2` 之后合入的用户可见变更，并排除纯开发流程改动。

#### Scenario: 用户查看版本更新
- **WHEN** 用户查看 README 的当前版本与近期功能
- **THEN** 可以找到内嵌封面导出、文件夹自动刷新、搜索源可用性与语种适配的简明说明

### Requirement: 发布前复核近期功能
发布前 MUST 复核 `v0.1.2` 以来用户可见功能变更，发现缺陷时在批准范围内修复并提供回归证据。

#### Scenario: 复核未发现缺陷
- **WHEN** 复核完成且没有 blocker 或 major 问题
- **THEN** 记录复核范围、验证证据和无问题结论

#### Scenario: 复核发现可修复缺陷
- **WHEN** 复核发现落在既有功能规格内的明确缺陷
- **THEN** 修复缺陷并以针对性回归验证覆盖
