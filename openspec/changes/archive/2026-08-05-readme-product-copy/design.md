# readme-product-copy 设计

## Context

README 现状「项目简介」+「核心特性」两节为内部约束口吻，混入非功能约束措辞（目标播放器/无批量/无在线曲库/无账号）与 AI 味文案。需改为产品视角、简约、去 AI 味。

## Goals / Non-Goals

**Goals:**
- 产品视角介绍：读者看到「是什么、为什么有用、能做什么」。
- 简约：定位一段 + 功能清单式枚举。
- 少 AI 味：不用「赋能/一站式/利器/优雅地」空泛词，不用感叹号/emoji，克制准确。

**Non-Goals:**
- 不改技术栈/常用命令/文档入口/协作流程四节（仓库文档属性）。
- 不新增产品功能描述之外的承诺。

## 技术方案

纯文档变更，作用于仓库根 `README.md`。范围限定：「项目简介」「核心特性」两节替换为产品文案 v2；「技术栈」「常用命令」「文档入口」「协作流程」四节逐字保留，不做任何改动。

- **替换边界**：仅重写「项目简介」与「核心特性」两节（README 第 3–17 行）。第 19 行起的「技术栈」节及其后三节保持原样。
- **文案来源**：产品文案一字不差取自 Decision 1 的 markdown 块，杜绝自行扩写（文案已定稿批准，不新增产品承诺）。
- **删除范围**：「目标播放器：用户自研播放器 + Slat Player。无批量（批量是 V2）、无在线曲库、无账号。」整句删除；「核心特性」小节标题改为「功能特性」。
- **验收方式**：机器可核验的 `grep` + `git diff`（见 tasks.md G1），无需构建/测试，无 Tauri 契约改动。

## 关键技术决策

- **不引入任何代码/依赖**：本变更零代码、零测试、零 Tauri 契约改动；`npm run build`、`cargo test` 均不受影响。技术栈、file layout、Tauri command 契约全部不触碰，故无须对其再设计。
- **文案锁定为定稿内容**：Decision 1 已获用户批准，这是唯一强制确认点；实现时照抄，不允许发挥/润色（防止「AI 味」回潮与超需求承诺）。
- **功能枚举与产品实际对齐**：自动搜索一节按已实施的多源现状书写（网易云、QQ 音乐、酷狗、LRCLIB、iTunes 五源，见 commit 6d98ab9 搜索源翻新），避免与 code 事实脱节。

## 变更域判断

**域：`frontend`（文案/文档，无 Rust 后端影响）。**

依赖顺序：本变更仅触碰 `README.md`，与 Rust 后端（`src-tauri/`）零耦合。按「Rust→Vue」的默认串行原则，本变更不依赖任何后端改动，也无需任何前置子变更；可独立开发、独立 CR、独立合并。无 worktree 并行需求。

## 任务拆分

见 `tasks.md`：单组 G1（README 文案替换），纯文档、串行单步，无前后端分工。

## Decisions

### 1. 文案结构（定稿，用户已批准）

```markdown
## 项目简介

MusicTag 是一个跨平台桌面应用，为本地音乐文件补全元数据。

## 功能特性

- **支持格式**：FLAC / MP3
- **编辑音乐标签**：歌名、作者、专辑、专辑作者、音轨号、年份、流派
- **编辑封面**：点选或拖拽嵌入图片
- **编辑歌词**：内嵌歌词，可同时导出 .lrc
- **自动搜索**：选中歌曲后，对缺失的歌词与封面自动联网搜索（网易云、QQ 音乐、酷狗、LRCLIB、iTunes 多源并发），候选手动点选后写入
```

### 2. 删除内容

原「目标播放器：用户自研播放器 + Slat Player。无批量（批量是 V2）、无在线曲库、无账号。」整句删除；「核心特性」节被「功能特性」替换。

## Risks

- 无（纯文档，零代码/零测试改动；`npm run build`、`cargo test` 均不受影响）。
